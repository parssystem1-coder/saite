### ۲) ترتیب اجرا

فازها را **به ترتیب ۱ → ۲ → ۳ → ۴ → ۵ → ۶** اجرا کن، مگر اینکه کاربر ترتیب دیگری بخواهد:

1. **فاز ۱ — Type Safety:** حذف `as any` ها با تایپ‌های تولیدی Prisma، نگاشت P2002→۴۰۹ / P2025→۴۰۴، قاعدهٔ eslint
2. **فاز ۲ — Performance DB:** pg_trgm + ایندکس GIN جستجو، ۷ ایندکس ترکیبی، endpoint سبک sitemap
3. **فاز ۳ — امنیت تکمیلی:** pino redact برای PII، rate-limit روی ۹ مسیر جامانده، جدول سیاست متمرکز، job retention
4. **فاز ۴ — Jobs:** انقضای PaymentIntent، مصرف idempotent outbox، جداسازی claimedAt از retryCount
5. **فاز ۵ — الگوهای طراحی:** Registry پرداخت، Unit of Work، paginatedList مشترک، getSiteUrl متمرکز
6. **فاز ۶ — تست‌های integration واقعی:** ۶ سناریوی race روی Postgres واقعی، e2e پرداخت mock، CI job

جزئیات کامل هر فاز (کد نمونه، SQL، فایل‌های دقیق) در سند مرجع است — از خودت طرح جدید اختراع نکن.

### ۳) قوانین سخت (نقض‌ناپذیر)

- **Contract-first:** امضای هیچ تابعی در `src/lib/api.ts` تغییر نکند
- **Mock adapterها حذف نشوند** — فقط stub بمانند؛ در production همیشه fail-closed
- **بدون تغییر ساختار اصلی** — فقط refactoring و بهبود طبق سند
- **قبل از هر commit:** `npm run type-check && npm run lint && npm run test && npm run build` — هر چهار مرحله باید سبز باشد
- پیام‌های commit **فارسی** طبق نمونه‌های داخل سند مرجع
- فقط روی برنچ سشن جاری کار کن و به همان push کن
- اگر `npx prisma generate` در sandbox به‌خاطر قطع شبکهٔ باینری شکست خورد: تایپ‌ها را بر اساس schema دستی تعریف کن یا آن آیتم را با ذکر دلیل به تعویق بینداز — build پروژه بدون generate هم سبز می‌ماند (Proxy در `src/server/shared/db.ts`)
- migration جدید فقط با الگوی موجود (`CREATE INDEX IF NOT EXISTS` + کامنت فارسی + همگام‌سازی `@@index` در schema)

### ۴) روال هر فاز

1. آیتم‌های فاز را از «جدول ردیابی» سند مرجع بخوان
2. قبل از تغییر، وضعیت فعلی کد را راستی‌آزمایی کن (شاید چیزی از قبل درست شده باشد)
3. تغییرات را اعمال کن — کوچک و متمرکز
4. چهار مرحلهٔ verify را اجرا کن
5. با دستورات git داخل همان فاز از سند مرجع commit و push کن
6. «جدول ردیابی» را در `docs/REMEDIATION-PLAN-2026-08-14.md` با ✅ به‌روزرسانی و commit کن
7. خلاصهٔ فارسی بده: چه شد، چه تست شد، چه چیزی به تعویق افتاد و چرا
8. **قبل از رفتن به فاز بعد، از کاربر تأیید بگیر**

### ۵) معیار پایان هر فاز

معیار پذیرش دقیق هر فاز در سند مرجع نوشته شده (مثلاً فاز ۱: «grep as any حداکثر ۳ مورد مستدل»؛ فاز ۲: «EXPLAIN ANALYZE → Bitmap Index Scan»). فازی که معیارش برآورده نشده را «تمام» اعلام نکن — یا کامل کن یا شفاف بگو چه چیزی و چرا باقی ماند.
