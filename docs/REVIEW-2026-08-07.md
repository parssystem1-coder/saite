## ۱) خلاصه مدیریتی

### ۱.۱. برنامهٔ اصلی (`src/`) — از «ماکت» گذشته، به «پوستهٔ قابل تحویل» رسیده

ممیزی قبلی (`docs/FRONTEND_ARCHITECTURE_AUDIT_2026-08.md`، ۳ اوت) سه شکاف بحرانی داشت که **هر سه در کد فعلی رفع شده‌اند** (با شواهد تازه):

| شکاف ممیزی قبلی | وضعیت فعلی | شاهد |
|---|---|---|
| `/admin` بدون هیچ گارد | ✅ گارد سه‌لایه: `proxy.ts` (سرور) + `(panel)/layout.tsx` + `getAdminSession()` در route handler ها | `src/proxy.ts:1-60`، تست زنده: `GET /admin → 307`؛ `src/app/admin/(panel)/layout.tsx` |
| `/products` صفر محتوای سرور | ✅ `<h1>` + توضیح سمت سرور | `src/app/products/page.tsx:37-62` (کامنت صریح «چرا عنوان اینجاست»)؛ خروجی curl شامل `<h1>` است |
| صفحهٔ اصلی ۱۲ await پشت‌سرهم + ارسال `Product` کامل | ✅ `Promise.all` + نگاشت سبک | `src/app/page.tsx:36,50-53` (`toCompatibleItemSummary`) |

اضافه‌براین در کد فعلی: احراز هویت ادمین سمت سرور با کوکی `httpOnly` + HMAC (مستند در `docs/ADMIN_AUTH_SERVER_SIDE.md`)، TOTP، audit log، rate limit سرور، ۶ فایل `error.tsx`، ۸ فایل `loading.tsx`، ۴۹۶ تست سبز.

**اما چهار شکاف ساختاری باقی است که الان باید بسته شوند:**

1. **مرجع قیمت هنوز کلاینت است** — `src/store/cart-store.ts` قیمت را در `localStorage` نگه می‌دارد و `src/components/checkout/checkout-client.tsx:26,61` مبلغ پرداخت را از `totalPrice()` کلاینت می‌گیرد. راه‌حل آماده در «New folder» هست (`price-authority.ts`) ولی **اعمال نشده**.
2. **هدرهای امنیتی HTTP صفر است** — `next.config.ts` (فقط ۳۸۶ بایت) هیچ `headers()` ندارد؛ نه CSP، نه `X-Frame-Options`، نه `Referrer-Policy`. پچ آماده در «New folder» هست (`security-headers.ts`) ولی اعمال نشده.
3. **نشست ادمین غیرقابل ابطال است** — `src/lib/auth/server/session-token.ts` فیلد `revision/version` ندارد؛ عوض کردن رمز، کوکی‌های قبلی را نمی‌بندد. پچ آماده هست.
4. **۲۰ صفحه از ۲۹ صفحهٔ ادمین هنوز placeholder است** — `AdminModulePage` (شواهد: `grep -rl AdminModulePage src/app/admin | grep page.tsx | wc -l → 20`).

### ۱.۲. بستهٔ «New folder» — ارزشمند اما **به‌صورت فعلی غیرقابل انتقال**

«New folder» دو بسته است:

- **`saite-product-editor/`** (۳۰ فایل): **نسخهٔ قدیمی‌تر** کدی که همین حالا در `src/` مرج شده — `diff` نشان می‌دهد نسخهٔ `src/` جدیدتر است (fallback به mock-adapter، import فایل CSS، اصلاحات z-index). علاوه‌برآن **یک فایل خراب دارد**: `RichTextEditor.tsx` با `\'use client\';` (کوئوت escape‌شده) شروع می‌شود → خطای نحوی → شکستن tsc. **نباید کپی شود؛ مرج کورکورانه = ریگرشن.**
- **`saite-arena-final-complete-payment/`** (۱۰ زیربسته): شامل **ماژول‌های جدیدی که در `src/` نیستند** — هستهٔ دامنه (OrderSnapshot/InventoryReservation)، قواعد حمل، قواعد پرداخت، تایپ‌های مشتری/سفارش، پچ سخت‌سازی (headers/revocation/price-authority/rate-limit) و مستندات. این‌ها **با جابه‌جایی اصولی به `src/` ارزش واقعی دارند**، اما: صفحات settings فقط **دموی استاتیک** هستند (به libهای خودشان وصل نیستند)، تست ندارند (customers)، برخی فقط docs/HTML هستند (order-fulfillment)، و هیچ‌کدام در `src/lib/admin/nav.ts` لینک نشده‌اند.

**حکم کلی:** «کد سورس فایل‌ها **کامل نیست و قابل انتقال مستقیم نیست**» — اما به‌صورت **انتخابی و فازبندی‌شده** (فقط هسته‌های منطقی + تست‌ها، سپس UI متصل به آن‌ها) انتقال‌پذیر و ارزشمند است. جزئیات کامل در بخش ۶.

### ۶.۲. پاسخ صریح به سؤال شما

**«آیا کد سورس فایل‌ها کامل است و قابل انتقال به پروژه است؟»**

- **کامل نیست:** از ۱۰ زیربسته، فقط ۴ بسته کد اجرایی کامل دارند (shipping, domain, payments, hardening). `order-fulfillment` صفر کد دارد؛ `customers` بدون تست/UI است؛ صفحات settings دموی استاتیک‌اند (بدون اتصال به libها، بدون mock-adapter، بدون لینک nav)؛ هیچ‌کدام route API یا migration ندارند (که طبق MASTER-PLAN عمدی است، ولی یعنی **فعلاً قابل استفاده در UI نیستند**).
- **انتقال مستقیم ممکن نیست:** (الف) `@/` در فایل‌های بسته به `./src` ریپو اشاره می‌کند — درجای خودشان compile نمی‌شوند؛ (ب) یک فایل خراب (RichTextEditor) کل tsc را می‌شکند؛ (ج) چند فایل **قدیمی‌تر** از `src/` هستند و کپی کورکورانه ریگرشن می‌سازد؛ (د) تست‌های بسته‌ها در `tests/` ریپو نیستند و با `npm test` فعلی اجرا نمی‌شوند.
- **انتقال انتخابی شدنی است:** هسته‌های pure (rules/contracts/types + تست‌ها) با جابه‌جایی به `src/` و `tests/` بدون تغییر، سبز می‌شوند (وابستگی‌هایشان فقط `@/types/...` و vitest است که موجودند). UIها باید بازنویسی شوند تا به mock-adapter وصل شوند — الگوی آماده: `src/lib/product-editor/mock-adapter.ts` که همین الان در src هست.

## ۷) سه کار بعدی (صریح، بدون تعارف)

1. **فاز ۰ — «New folder» را از درخت ریپو خارج کن (یا حداقل `tsconfig.exclude` + gitignore کن).** الان `npm run type-check` و `npm run build` روی سیستم شما و CI **شکسته‌اند** و دلیلش فقط همین پوشه است. بدون این، هیچ کار دیگری معنا ندارد. (من در این سشن ثابت کردم: با کنار گذاشتن موقت پوشه، هر دو سبز می‌شوند — ۶۰ route.)
2. **فاز ۱ — پچ سخت‌سازی را diff-سهوی اعمال کن:** `security-headers.ts` + `next.config.ts` (CSP/X-Frame/Referrer)، `session-token` با `revision` (ابطال نشست)، `rate-limit` per-username، و ۴ تست همراه. این ارزان‌ترین برد امنیتی موجود است چون کد آماده است.
3. **فاز ۲ — `price-authority.ts` را بیاور و checkout را به آن وصل کن** (مبلغ مرجع فقط از `getProductsByIds`؛ `totalPrice()` کلاینت فقط نمایشی). این مهم‌ترین شکاف تجاری است: الان مبلغ «پرداخت» از localStorage می‌آید.

**چه چیزی کم است (که در بسته‌ها نیست):** هیچ adapter پرداخت واقعی؛ هیچ mock-adapter برای shipping/payments settings؛ تست برای customers/orders؛ لینک nav برای صفحات جدید؛ OG image؛ E2E؛ یک سند وضعیت واحد (docs فعلی منقضی‌اند).

**چه چیزی اضافه است (باید حذف شود):** کل `saite-product-editor/` در «New folder» (تکراری + قدیمی + یک فایل خراب)؛ `admin-login-hardening` (قدیمی‌تر از src)؛ HTML previewهای بسته‌ها (فقط مرجع)؛ `docs/ARCHITECTURE_REVIEW.md` و `UI_SHELL_AUDIT_AND_PLAN.md` (منقضی — آرشیو شوند)؛ `DATABASE_URL` و متغیرهای بی‌مصرف در `.env.example` (پچ نسخهٔ پاک‌شده دارد).
