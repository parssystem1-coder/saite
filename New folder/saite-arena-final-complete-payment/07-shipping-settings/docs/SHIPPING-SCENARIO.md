# سناریو کامل تنظیمات حمل‌ونقل

## جایگاه منو

`پنل مدیریت → تنظیمات → حمل‌ونقل و ارسال`

زیرمنوها: روش‌های ارسال، شرکت‌های حمل، مناطق پوشش، قوانین قیمت‌گذاری، بیمه و بسته‌بندی. سفارش‌ها و checkout مصرف‌کننده این تنظیمات‌اند، نه محل تعریف آن‌ها.

## سه مدل پرداخت، جدا از مدل قیمت‌گذاری

### پیش‌کرایه، `prepaid`
مشتری هنگام checkout هزینه حمل را می‌پردازد. قیمت می‌تواند ثابت، وزن‌محور، حجمی، نرخ شرکت یا ترکیبی باشد.

### پس‌کرایه، `cash_on_delivery`
مبلغ حمل از checkout حذف می‌شود و شرکت حمل هنگام تحویل از گیرنده دریافت می‌کند. این ارسال رایگان نیست. checkout باید مبلغ تخمینی/سیاست شرکت را واضح نشان دهد و سفارش باید carrier cost، پرداخت‌کننده، وضعیت وصول و متن هشدار را snapshot کند.

### ارسال رایگان، `free`
مشتری صفر می‌پردازد، اما فروشگاه هزینه را می‌دهد. باید شرط آن مشخص باشد: حداقل مبلغ، کمپین، سگمنت مشتری، شهر، دسته محصول یا سقف وزن. هزینه واقعی فروشگاه در گزارش مالی حفظ شود.

## مدل قیمت‌گذاری مستقل

`free`, `flat_rate`, `weight_based`, `dimensional_weight`, `carrier_rate`, `hybrid`.

این دو لایه عمداً جدا هستند: مثلاً `prepaid + flat_rate`، `prepaid + weight_based`، `cash_on_delivery + carrier_rate` و `free + free` معتبرند. `cash_on_delivery + free` به‌عنوان «پس‌کرایه واقعی» نباید بدون هشدار پذیرفته شود.

## فیلدهای مدیریتی

شرکت حمل: نام، کد، لینک tracking، تلفن، فعال بودن، پشتیبانی پس‌کرایه و بیمه.

روش ارسال: نام مشتری‌پسند، شرکت، سرویس، مدل پرداخت، مدل قیمت، نرخ ثابت، نرخ پایه، نرخ هر کیلو، ضریب حجمی، بیمه، هزینه بسته‌بندی، هزینه خدمات، شرط ارسال رایگان، حداقل/حداکثر مبلغ، سقف وزن/ابعاد، مناطق، دسته‌های مجاز، سگمنت مشتری، بازه تحویل، توضیح checkout، اولویت و وضعیت.

## جریان checkout

1. مشتری آدرس و اقلام را ثبت می‌کند.
2. سرور وزن، ابعاد، شهر، دسته محصول، ارزش سفارش و سگمنت را محاسبه می‌کند.
3. فقط روش‌های واجد شرایط نمایش داده می‌شوند.
4. برای پس‌کرایه پیام هشدار و تایید صریح نشان داده می‌شود.
5. برای رایگان علت رایگان بودن نمایش داده می‌شود، مثل «رایگان برای سفارش‌های بالای ۵ میلیون تومان».
6. انتخاب روش در Order Snapshot ذخیره می‌شود.

## Order Snapshot

ذخیره کنید: methodId، carrierId، service، paymentMode، pricingModel، customerPayable، carrierCost، storeSubsidy، insurance، packaging، ruleId، label/description، timestamp و نسخه تنظیمات. تغییر آینده تنظیمات نباید سفارش قدیمی را تغییر دهد.

## قواعد جلوگیری از خطا

- دو قانون هم‌زمان روی یک سفارش اعمال نشود؛ priority و ruleId لازم است.
- پس‌کرایه با برچسب «ارسال رایگان» نمایش داده نشود.
- شرکت حمل باید واقعاً COD را پشتیبانی کند.
- روش نامناسب برای وزن/ابعاد/منطقه اصلاً به مشتری نشان داده نشود.
- هزینه واقعی شرکت و یارانه فروشگاه از مبلغ مشتری جدا بماند.
- تغییر روش حمل بعد از چاپ لیبل، لیبل قبلی را invalid کند و audit بسازد.
- پس از ثبت سفارش، snapshot immutable باشد.
