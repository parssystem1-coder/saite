# مشخصات حرفه‌ای ماژول مشتریان

## وضعیت فعلی

مسیر `src/app/admin/(panel)/customers/page.tsx` در نسخه فعلی فقط `AdminModulePage` و placeholder را رندر می‌کند. مدل عمومی `AuthUser` نیز فقط id، نام، ایمیل و نقش دارد و برای CRM، آدرس، رضایت‌نامه، سفارش و مرجوعی کافی نیست.

## تصمیم محصول

ماژول مشتریان باید CRM عملیاتی باشد، نه فقط دفترچه تلفن. مدیر باید بتواند مشتری را پیدا کند، ارزش و رفتار او را بفهمد، آدرس تاییدشده را برای سفارش ببیند، پیگیری کند و سابقه تعامل را حفظ کند.

## فیلدهای پیشنهادی

### هویت و تماس

- شناسه داخلی مشتری
- نام و نام خانوادگی
- نام شرکت و نوع مشتری، حقیقی یا سازمانی
- موبایل تاییدشده
- ایمیل تاییدشده
- کد ملی یا شناسه ملی شرکت، فقط در صورت نیاز و با دسترسی محدود
- تاریخ ثبت‌نام، آخرین ورود و کانال جذب

### وضعیت و سگمنت

- فعال، غیرفعال، مسدود، در انتظار پیگیری
- VIP، سازمانی، خریدار تکراری، مشتری جدید، در معرض ریزش، بدون خرید
- برچسب‌های سفارشی
- امتیاز وفاداری
- مسئول پیگیری و تاریخ پیگیری بعدی

### ارزش تجاری

- تعداد سفارش
- مبلغ کل خرید
- میانگین ارزش سفارش
- آخرین سفارش
- تعداد مرجوعی و مبلغ refund
- تخفیف دریافتی
- ارزش پیش‌بینی‌شده مشتری در آینده

### آدرس‌ها

- چند آدرس ذخیره‌شده با عنوان منزل، محل کار یا انبار
- نام گیرنده جدا از نام حساب
- شماره تماس آدرس
- استان، شهر، آدرس کامل، پلاک و واحد
- کدپستی ۱۰ رقمی
- آدرس پیش‌فرض
- timestamp تایید یا استفاده در آخرین سفارش

### رضایت و ارتباطات

- رضایت SMS، ایمیل، واتساپ و بازاریابی
- زمان و منبع رضایت
- opt-out مستقل برای هر کانال
- ترجیح کانال تماس
- تاریخچه پیام‌ها و تماس‌ها

### سوابق و پشتیبانی

- سفارش‌های اخیر
- مرجوعی‌ها و شکایت‌ها
- تیکت‌ها و پیام‌ها
- یادداشت داخلی با نویسنده و زمان
- یادداشت قابل مشاهده برای مشتری، جدا از یادداشت داخلی
- audit trail تغییرات مهم

## موارد طراحی‌شده در preview

- KPIهای کل مشتری، فعال، خریدار تکراری و پیگیری
- جستجوی نام، موبایل، ایمیل و شناسه
- فیلتر وضعیت و سگمنت
- تب‌های VIP، سازمانی، تکراری و پیگیری
- جدول با تماس، سگمنت، تعداد سفارش، ارزش خرید و آخرین فعالیت
- drawer جزئیات بدون ترک لیست
- ارزش طول عمر و امتیاز وفاداری
- آدرس پیش‌فرض قابل استفاده برای سفارش و چاپ
- سفارش‌های اخیر و timeline فعالیت
- یادداشت داخلی و اقدام ارسال پیام

## امنیت و حریم خصوصی

- صفحه و endpoint فقط برای admin و نقش‌های مجاز باشند.
- کد ملی، آدرس و تماس را در URL، analytics یا log عمومی قرار ندهید.
- خروجی CSV باید permission جدا و audit داشته باشد.
- export با escape فرمول‌های Excel تولید شود تا CSV injection رخ ندهد.
- آدرس کامل فقط با نیاز عملیاتی نمایش داده شود، نه در جدول اصلی.
- اطلاعات مشتری در cache عمومی قرار نگیرد و پاسخ‌ها `no-store` باشند.
- حذف مشتری باید soft delete و مطابق سیاست نگهداری سفارش انجام شود.
- رضایت بازاریابی باید قابل اثبات، timestampدار و قابل لغو باشد.

## اتصال به checkout و سفارش

آدرس داخل customer profile فقط address book است. در زمان create order باید یک snapshot از آدرس، نام گیرنده و تلفن داخل سفارش ذخیره شود؛ اگر مشتری بعداً آدرس را عوض کرد، لیبل و فاکتور سفارش قدیمی نباید تغییر کند.

## مدل API پیشنهادی

- `GET /api/admin/customers?q=&status=&segment=&page=`
- `GET /api/admin/customers/:id`
- `PATCH /api/admin/customers/:id`
- `POST /api/admin/customers/:id/notes`
- `POST /api/admin/customers/:id/tags`
- `GET /api/admin/customers/:id/orders`
- `GET /api/admin/customers/:id/activity`
- `POST /api/admin/customers/:id/follow-up`
- `POST /api/admin/customers/export`

همه endpointها باید `getAdminSession()` و permission دقیق عملیات را بررسی کنند.

## معیار پذیرش

- جدول روی موبایل قابل استفاده باشد و جزئیات در drawer تمام‌صفحه باز شود.
- جستجو با موبایل، نام، ایمیل، شرکت و شناسه کار کند.
- آدرس کامل فقط در جزئیات دیده شود.
- مشتری از سفارش به پروفایل و از پروفایل به سفارش قابل پیمایش باشد.
- سگمنت‌ها از داده سفارش و رفتار قابل محاسبه باشند، نه فقط متن دستی.
- یادداشت داخلی و پیام مشتری قاطی نشوند.
- export و تغییر وضعیت audit شوند.
- هیچ مبلغی از localStorage یا داده کلاینتی به‌عنوان lifetime value معتبر پذیرفته نشود.
