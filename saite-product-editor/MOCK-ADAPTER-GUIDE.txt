Saite Product Editor, Mock Adapter Guide
========================================

هدف
----
در مرحله طراحی UI، بدون بکند و دیتابیس واقعی، تمام رفتارهای فرم را با localStorage شبیه‌سازی می‌کنیم. بعداً فقط adapter را با HTTP adapter عوض می‌کنیم. UI به route، دیتابیس یا فایل‌سیستم وابسته نیست.

فایل‌ها
-------
- src/lib/product-editor/adapter.types.ts: قرارداد مشترک بین UI، mock و بکند واقعی.
- src/lib/product-editor/mock-adapter.ts: ذخیره draft، publish، ایموجی، نسخه و کپی داخل localStorage.
- src/lib/product-editor/http-adapter.ts: نمونه قرارداد برای API واقعی آینده.

روش استفاده در ProductEditor
-----------------------------
در کامپوننت client:

  const adapter = useMemo(() => createMockProductEditorAdapter(), []);

و عملیات‌ها را به adapter وصل کن:

  await adapter.saveDraft(state);
  const image = await adapter.uploadImage(file);
  const emojis = await adapter.addEmoji('🧩');

برای اتصال واقعی:

  const adapter = useMemo(() => createHttpProductEditorAdapter(), []);

همان UI کار می‌کند. لازم نیست پنل‌ها بازنویسی شوند.

رفتار Mock
----------
- اطلاعات draft و publish در localStorage ذخیره می‌شود.
- تصویر با URL.createObjectURL فقط برای preview ساخته می‌شود و به سرور ارسال نمی‌شود.
- ایموجی‌های پیش‌فرض همیشه وجود دارند و ایموجی جدید در کتابخانه محلی ذخیره می‌شود.
- نسخه‌ها و کپی محصول شبیه‌سازی می‌شوند.
- تاخیر کوتاه مصنوعی برای نمایش loading واقعی دارد.
- برای پاک‌سازی: localStorage را پاک کن یا کلیدهای saite.product-editor.* را حذف کن.

نکته مهم
--------
URL مربوط به blob فقط preview است و نباید وارد JSON-LD یا دیتابیس شود. در API واقعی، uploadImage باید URL پایدار CDN برگرداند.

پیشنهاد اتصال در آینده
----------------------
1. ابتدا storage تصویر را بساز و uploadImage را به آن وصل کن.
2. سپس saveDraft و publish را به endpoint محصول وصل کن.
3. بعد emoji را به جدول custom_emojis دیتابیس وصل کن.
4. نسخه‌بندی و audit log را در بکند نگه دار.
5. احراز هویت و permission را روی تمام عملیات ادمین اجباری کن.
